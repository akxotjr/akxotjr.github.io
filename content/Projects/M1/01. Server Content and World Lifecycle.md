## Server Composition

`M1_Server`는 `ServerNetworkManager`에 M1 전용 authentication, character, social, world-content 구현을 연결한다. 시작 시 shared-data manifest와 world contents를 읽고 static world instance를 bootstrap한다.

| Component | Responsibility |
| --- | --- |
| `AuthenticationContent` | password credential을 account ID로 검증 |
| `CharacterContent` | character list/select content request 처리 |
| `CharacterSessionStore` | 선택한 character와 현재 player actor binding 관리 |
| `WorldContent` | player actor materialization, leave/rollback, physics event 연결 |
| `PortalSystem` | portal trigger를 world transition request로 변환 |
| `SocialContent` | text chat validation과 audience별 delivery |

## Authentication and Character Selection

인증은 password credential만 받는다. `AccountStore`가 login ID와 password가 모두 일치할 때 account ID를 반환하고, 실패하면 invalid account로 완료한다.

Ready가 된 client는 generic content request로 character 목록을 받고, 선택 request에는 FlatBuffers `fbCharacterSelectRequest`의 character ID를 보낸다. 서버는 선택한 character가 해당 account 소유인지 확인한 뒤 `CharacterSessionStore`에 저장하고 `fbCharacterSelectResponse`를 반환한다.

```text
password credential
    -> AuthenticationContent
    -> character list request
    -> owned character select
    -> CharacterSessionStore
    -> enter-world destination resolution
```

선택이 완료되기 전에는 enter-world destination resolver가 값을 반환하지 않는다. 선택한 character의 `worldArchetypeKey`가 첫 입장 archetype을 결정한다.

## World Materialization and Transition

`WorldContent::PrepareMemberContent()`은 요청 entry point 또는 world의 default spawn을 선택하고, character session의 materialization을 시작한다. `SpawnPlayerAsync()` 성공 뒤에만 target world와 actor ID binding을 확정하며, spawn position을 character state에 반영한다.

```text
enter request
    -> BeginMaterialization(token, target world)
    -> resolve spawn and spawn player actor
    -> CompleteMaterialization(target actor binding)
    -> commit source leave and despawn source actor
```

전환 중 실패하면 target actor를 제거하고 `FailMaterialization()` 또는 `RollbackMaterialization()`으로 이전 binding을 복구한다. Source leave를 commit할 때는 authoritative actor state에서 position을 읽어 character location을 갱신한 뒤 이전 actor를 despawn한다.

### Static Field Instances and Portals

world contents에는 하나의 `Field` archetype과 `field-01`–`field-10` static instance가 정의되어 있다. 각 instance의 left/right route는 인접 field를 연결하며, 양 끝은 `field-10`과 `field-01`을 연결한다.

`PortalSystem`은 world 초기화 때 content에 지정된 portal actor에 `PortalComponent`를 붙인다. Physics `TriggerFound` event에서 trigger actor와 controlled player actor를 검증한 뒤, destination archetype, explicit instance, arrival spawn을 담은 `EnterWorldRequest`를 제출한다. 따라서 portal 전환은 client가 목적지를 직접 신뢰시키는 흐름이 아니라 server-side physics event에서 시작한다.

## Social Content

M1 text chat의 content type은 `1`이며 FlatBuffers payload를 검증한다. text는 비어 있거나 512 byte를 넘을 수 없고, UTF-8이어야 하며 client가 sender name을 채워 넣을 수 없다. 서버는 선택된 character name으로 새 payload를 만든다.

| Audience | Validation and delivery |
| --- | --- |
| Global | recipient 없이 `scopeId == 0`; 모든 user에게 broadcast |
| Group | sender의 main world ID와 `scopeId`가 같을 때 그 world에 전달 |
| Direct | character ID 또는 name으로 online user를 찾고, recipient와 sender에게 전달 |

## Current Limits

account, character, selected-character session은 memory-only store다. Server process 재시작 뒤에 저장 상태를 복구하지 않으며, server startup code가 test account와 Bot account를 등록한다. World content data에 없는 spawn, portal actor 또는 destination은 initialization/transition을 진행하지 않는다.

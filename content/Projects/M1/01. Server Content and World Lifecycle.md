## Server Composition

`M1_Server`는 `ServerNetworkManager`에 M1 전용 authentication, character, social, world-content 구현을 연결한다. 시작 시 shared-data manifest와 world contents를 읽고 static world instance를 bootstrap한다.

| Component               | Responsibility                                                 |
| ----------------------- | -------------------------------------------------------------- |
| `Authenticator`         | `IAuthenticator` 구현으로 password credential을 account ID로 검증      |
| `CharacterContent`      | character list/select content request 처리                       |
| `CharacterSessionStore` | 선택한 character와 현재 player actor binding 관리                      |
| `WorldContent`          | player actor materialization, leave/rollback, physics event 연결 |
| `PortalSystem`          | portal trigger를 world transition request로 변환                   |
| `SocialContent`         | text chat validation과 audience별 delivery                       |

## Authentication and Character Selection

인증은 password credential만 받는다. `AccountStore`가 login ID와 password가 모두 일치할 때 account ID를 반환하고, 실패하면 invalid account로 완료한다.

Ready가 된 client는 generic content request로 character 목록을 받고, 선택 request에는 FlatBuffers `fbCharacterSelectRequest`의 character ID를 보낸다. 서버는 선택한 character가 해당 account 소유인지 확인한 뒤 `CharacterSessionStore`에 저장하고 `fbCharacterSelectResponse`를 반환한다.

```text
password credential
    -> Authenticator
    -> character list request
    -> owned character select
    -> CharacterSessionStore
    -> enter-world destination resolution
```

선택이 완료되기 전에는 enter-world destination resolver가 값을 반환하지 않는다. 선택한 character의 `worldArchetypeKey`가 첫 입장 archetype을 결정한다.

## World Materialization and Transition

M1의 `WorldContent`는 Jam이 제공하는 membership hook을 구현하여 character session과 Player actor를 연결한다. membership 검증·준비와 Player 생성을 서로 다른 hook에서 수행한다. target membership이 등록되어도 replication은 `Suspended`이며, 이 시점에는 Player를 생성하지 않는다. 엔진의 전환·동기화 계약은 [[Projects/Jam/Game World/01. World Entry and Transition|World Entry and Transition]]에서 설명한다.

| Hook | M1 content 처리 |
| --- | --- |
| `OnJoiningMembership()` | 선택된 character의 account 소유권, spawn과 첫 입장 archetype 검증 |
| `OnPreparedMembership()` | rollback용 character 상태 보관, `BeginMembershipMaterialization()`과 진입 위치 준비 |
| `OnCommittedMembership()` | membership 전환의 materialization을 수락하고 준비 단계의 보관 상태 정리 |
| `OnActivatedMembership()` | client world 적용과 transport 준비 뒤 Player 생성 및 actor binding 확정 |

기본 입장에서는 character에 보관된 위치를 사용하고, 명시적인 entry point가 있으면 해당 spawn 위치를 사용한다. Bot은 traverse lane과 phase로 계산한 분산 위치를 사용한다. 준비 단계에서 의도한 위치를 character state에 반영하고, activation 성공 시 실제 spawn 위치를 다시 반영한다.

```text
enter request
    -> source membership detach (source가 있을 때)
    -> target JoinMembership
        -> OnJoiningMembership
        -> member 등록 / pending activation 저장
        -> OnPreparedMembership / BeginMembershipMaterialization
    -> authoritative main world commit
    -> target entry 확정 / OnCommittedMembership
    -> source leave 정리 / source actor despawn (source가 있을 때)
    -> membership transition 성공 응답 / main world 변경 통지
    -> client world prepare / commit 적용 확인
    -> TCP + UDP 준비 확인
    -> ActivateMemberReplication / OnActivatedMembership
        -> SpawnPlayerAsync / physics·control·AOI binding
        -> CompleteMembershipMaterialization / actor binding 확정
    -> ResumeMemberReplication / InitialSync
```

`OnDetachingMembership()`은 source actor의 authoritative position과 기존 binding을 보관한다. 전환 중 target 준비가 실패하면 `OnRollbackMembership()`이 준비 중인 actor를 정리하고 `CancelMembershipMaterialization()`과 보관된 character 위치로 target 준비를 되돌린다. source 복구는 `OnRestoredMembership()`에서 기존 Player binding과 위치를 복원한다. 성공 경로에서는 `OnRemovedMembership()`이 source actor를 despawn하고 `FinalizeMembershipSource()`로 이전 binding을 정리한다.

Player 생성은 이 membership 전환이 완료된 뒤 별도 world sync의 activation에서 수행한다. `SpawnPlayerAsync()` 성공 후 `CompleteMembershipMaterialization()`과 위치 갱신까지 성공해야 target actor binding을 수락한다. activation 도중 실패해 actor가 남으면 해당 actor를 제거하고 `ResetMembershipActivation()`으로 재시도할 수 있게 정리한다. world sync는 activation 실패를 deadline 안에서 재시도하며, sync 실패·timeout은 disconnect 경로로 처리한다.

따라서 enter 성공 응답은 Player 생성 완료를 의미하지 않는다. client가 현재 world를 적용한 뒤 서버가 Player를 생성하고 replication을 재개하며, visible actor의 baseline ACK 완료는 replication이 별도로 관리한다.

### Static Field Instances and Portals

world contents에는 하나의 `Field` archetype과 `field-01`–`field-10` static instance가 정의되어 있다. 각 instance의 left/right route는 인접 field를 연결하며, 양 끝은 `field-10`과 `field-01`을 연결한다.

`PortalSystem`은 world 초기화 때 content에 지정된 portal actor에 `PortalComponent`를 붙인다. Physics `TriggerFound` event에서 trigger actor와 controlled player actor를 검증한 뒤, destination archetype, explicit instance, arrival spawn을 담은 `EnterWorldRequest`를 제출한다. 따라서 portal 전환은 client가 목적지를 직접 신뢰시키는 흐름이 아니라 server-side physics event에서 시작한다.

## Social Content

M1 text chat의 content type은 `1`이며 FlatBuffers payload를 검증한다. text는 비어 있거나 512 byte를 넘을 수 없고, UTF-8이어야 하며 client가 sender name을 채워 넣을 수 없다. 서버는 선택된 character name으로 새 payload를 만든다.

| Audience | Validation and delivery |
| --- | --- |
| Global | recipient 없이 `scopeId == 0`; 모든 user에게 broadcast |
| Group | sender의 main world ID와 `scopeId`가 같을 때 그 world에 전달 |
| Direct | character ID 또는 name으로 online user를 찾고, recipient와 sender에게 전달 |

## Current Limits

account, character, selected-character session은 memory-only store다. Server process 재시작 뒤에 저장 상태를 복구하지 않으며, server startup code가 test account와 Bot account를 등록한다. World content data에 없는 spawn, portal actor 또는 destination은 initialization/transition을 진행하지 않는다.
